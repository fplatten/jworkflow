## Delivered flow

- Authenticated browser project form requires explicit root confirmation before project reads.
- One single-module Maven, Gradle Groovy or Gradle Kotlin Java project; configured Java targets below 17 and known mismatched core versions are rejected.
- Root-confined static Java source discovery proposes events, listeners, commands, record payload fields, packages and source locations without executing build scripts or loading classes.
- Package and in-root workflow output are explicitly confirmed. Source changes refresh discovery and expire that confirmation.
- `.jworkflow/workflow.jworkflow.json` stores one explicit incomplete draft using stable document ID, monotonic revision and external-edit SHA-256 precondition. Unknown schemas are left unchanged.
- `.gitignore` addition is previewed and separately approved against an unchanged base hash.
- Bundled document, project-profile and discovery JSON schemas plus `docs/core-capabilities.md` establish the M2 contracts.

## Web-application and macOS update (October 3, 2026)

Changes for the JAR delivery on Windows and macOS:

- **Linked ancestors (macOS blocker, fixed).** `confirm` stored the root with `toRealPath(NOFOLLOW_LINKS)` while discovery compared `toRealPath()` results. Under a linked ancestor (macOS `/tmp`, `/var/folders` → `/private/...`, which includes JUnit temp folders; Windows junctions) every source was skipped and discovery showed zero bindings. The root is now the fully resolved real path.
- **In-root link escapes (fixed).** `resolve` checked containment without following links, so an in-root link such as `src/main/resources/workflows` → outside directory, or a linked `.gitignore`, passed. Containment now compares fully resolved real paths, and the existing no-link checks on written files remain.
- **`.gitignore` line endings (fixed).** The addition used the OS separator, which mixes CRLF into LF files on Windows and the reverse on macOS. It now follows the file's existing convention (LF for new files).
- `scripts/m2-browser-smoke.mjs` updated for the M3 UI (Blockly replaced the raw block-state field): it saves an incomplete draft holding one unconfigured step, then reloads and re-confirms to prove reopen. It is now in the Windows/macOS CI matrix with Chrome and Edge.

## Known limitations and deferred qualification

- Discovery intentionally supports direct, common build declarations and source conventions. Arbitrary inherited Maven properties, Gradle convention plugins, complex Java syntax and semantic event-to-command transforms can remain unresolved and must be shown to the user rather than guessed.
- The M2 capability mapping exposes only the proved sequence, two-way branch, failure and symbolic action contracts needed to begin M3. Additional core constructs require proof before palette exposure.
- Blockly, generation, source proposals, AI and project command execution are not implemented in M2.
- Expanded junction/reparse-point, case-collision, permission/disk failure, source-race and schema-limit matrices remain M7 work. Windows and macOS process confinement remains M6 work before project command execution.
- Case-collision rejection (SEC-01) is not implemented yet; it matters for writes, which start in M4, on the case-insensitive default filesystems of both Windows and macOS.
