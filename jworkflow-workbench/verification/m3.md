# M3 build-first evidence register

**Status: functional checkpoint complete on Windows** (October 3, 2026). Tasks WB-10–WB-13 deliver the editor, Generate-only validation, canonical Groovy generation and shared Wasm validation. Detailed scale/performance, accessibility (screen reader), adversarial and final-coverage qualification remain M7 work (WB-25). macOS evidence is pending the owner's run and the CI matrix.

## Delivered

**WB-10 — Editor and save lifecycle**
- Blockly palette (Start, Step, Branch, End), canvas, inspector, problems, read-only preview and terminal.
- Explicit Save; incomplete drafts save; no autosave. Truthful unsaved/saved state.
- Session-only Undo/Redo; duplicate/delete, comments, collapse, zoom/pan/fit and block search.
- Keyboard authoring:
  - **Add block** inserts after the selected block, or at the end of the Start block, and focuses its name.
  - The inspector edits every block field, offering discovered commands and node names as suggestions.
  - The **Blocks** outline selects any block.
  - Clicking a problem selects its block and focuses the exact field. Metadata problems focus the name, engine ID or version.
- Duplicate copies only the selected block and its contents, with fresh IDs. Copied node names get a unique `-copy` suffix, and targets inside the copy are remapped. Undo removes the copy as one step.
- Deleting a container explains how many contained blocks go with it; following siblings are not counted.
- `/exit` with unsaved changes offers Save, Discard or Cancel. A failed save keeps Workbench open. Closing or reloading a tab with unsaved changes triggers the browser's leave-page warning.
- Rename derives the engine ID and keeps the document ID; the version never auto-increments.
- One workflow per project: extra `*.jworkflow.json` files in `.jworkflow/` make Workbench refuse to load or save, naming the files. It never picks one silently and never changes them.

**WB-11 — Generate-only validation**
- Generate saves first, then validates the saved revision. A failed save stops Generate.
- Errors block code; warnings (for example, a disabled detached block) do not.
- Diagnostics carry a stable code, severity, correction, block and field.
- Edits and discovery refreshes mark the preview and problems stale, and late results are ignored.
- There is no separate Validate action and no live checking.

**WB-12 — Canonical Groovy and preview**
- One backend emitter. Output is deterministic and independent of layout, and comes with a source map and compatibility metadata.
- Hostile strings stay literal, and decimals keep their precision.
- The pinned core compiles every generated definition before preview. Generate never writes the destination file; it only reports whether one already exists, with its hash.

**WB-13 — Shared Wasm validation**
- The bundled `jworkflow-rules-v1.wasm` runs three integer rules: required, maximum blocks and maximum depth.
- It runs in a Web Worker only on Generate, with a 1,500 ms limit. On failure, mismatch or timeout the UI shows that the backend fallback was used.
- The backend stays authoritative.

## Changes in this checkpoint

- Added the one-workflow check, keyboard insertion, inspector field editing, outline, field-level problem focus, duplicate renaming and the leave-page warning. Discovery changes now mark results stale.
- Problems for workflow metadata used to focus nonexistent element IDs; they now focus the right fields.
- **Wasm parity defect fixed.** The module compared counts unsigned (`i32.gt_u`) while Java compares signed. A shared fixture exposed the difference at −1. The WAT now uses `i32.gt_s`, rebuilt with binaryen `version_123`:

  ```
  wasm-as src/main/resources/wasm/jworkflow-rules-v1.wat -o src/main/resources/static/vendor/jworkflow-rules-v1.wasm
  ```

  The module is still 109 bytes; SHA-256 changed from `c9fd7390…` to `59c57dd76436f3d45da3172e6579afe737c28cfca2af4f09f258b54a35f797b9`.
- `scripts/jar-smoke.mjs` now exits explicitly. node-pty's Windows console handles kept Node alive after a passing run, which would have hung CI.

## Core semantics found

A generated step does not run when an instance starts. The pinned core runs a step's handler when the instance receives a signal (event). The execution test sends one signal after start, mirroring a listener-delivered event. This matches the PRD model (listeners turn events into commands) and should inform the M4 integration plan's wiring instructions.

## Known limitations and deferred qualification

- Blockly's own context-menu Duplicate and copy/paste give fresh IDs but do not rename node names. The resulting duplicate-name error shows on Generate. Only the toolbar Duplicate renames.
- Deleting with the Delete key or the trash can skips the container explanation; the toolbar Delete shows it.
- The Wasm subset is intentionally small: three integer rules shared exactly with Java. It is hand-written WAT checked against a shared fixture, not Java compiled with GraalVM Web Image. See G-16 for the decision.
- Not yet done (M7):
  - scale and latency budgets (500 blocks / 100 variables / 10 levels, 100 ms edits, 2 s save/reopen, Generate latency)
  - screen-reader walkthrough
  - malformed, oversized and hostile document corpora beyond the current fixtures
  - final coverage gates. Branch coverage is still below 80%; `mvnw verify` fails as recorded in WB-04.
- Not run on macOS.
