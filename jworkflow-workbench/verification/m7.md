- checks that `jworkflow-core` is bundled and that JDBC and native-image artifacts are not

## Coverage (WB-25, G-17)

`mvnw -o verify` passes both independent gates: **line 94.3%, branch 81.2%** (budgets 80%/80%). `scripts/verify-gates.ps1` proves each gate rejects a controlled shortfall.

CI enforces the gate on the Windows job. The macOS job runs different platform-specific code and builds without the gate.

**To reach the gates, tests were added for real behavior, with no production exclusions:**
- `ValidationMatrixTests`, `ProposalAndToolingTests` and `ScaleTests`
- more cases in `AssistantServiceTests` and `CommandServiceTests`

**Defects those tests found and fixed:**
- **Identical targets:** a step or branch whose two routes go to the same node passed validation but was rejected by the core. It is now a `TARGETS_IDENTICAL` error on the field.
- **500-block workflows rejected as invalid JSON:** Blockly nests each chained block about two levels deep, beyond Jackson's default nesting limit of 500. A bounded limit of 2,500 now applies to workflow documents.
- **Document size limit exceeded:** pretty-printing a 500-block document grew quadratically, past 2 MiB. Documents are now written compactly (66 KB at 500 blocks).
- **Late completion after cancel:** a cancelled or `/exit`-abandoned AI request could leave its thread waiting out the 10-minute deadline. Cancel and shutdown now release it.

## Accessibility (AT-16)

`AccessibilityBrowserIT` on Chrome and Edge runs the core journey with the **keyboard only**. Every control is reached with Tab and activated with keys:
- confirm project, settings, name and version
- insert and configure start, step and two ends through **Add block** and inspector fields
- Save, Generate, and reading the preview

It also audits every visible control for an accessible name and checks that a visible focus style exists. Ten consecutive runs (20 journeys) passed.

**Defects found and fixed:**
- **Keyboard trap:** the terminal trapped Tab, because xterm consumed it, so keyboard users could not leave it (WCAG 2.1.2). Tab and Shift+Tab now move focus.
- **Unnamed canvas:** Blockly's focusable canvas group had `role=none` and no name. It is now a labeled group that points to the keyboard editing paths.
- **Focus lost after insertion:** after a keyboard insertion, Blockly sometimes moved focus to the block or the page body after the name field was focused. Workbench now restores the field for a short window, but only from the body or canvas, never from a control the user chose.

**Not run:** a screen-reader walkthrough (NVDA or Narrator on Windows, VoiceOver on macOS). This needs a person.

## AI-05 failure diagnosis (completed in M7)

After `/build` or `/test`, **Share output with the assistant…** previews the exact last 4,000 characters, with secrets redacted:
- **Redacted:** bearer and basic authorization, `password`/`token`/`secret`/`api key` values, private-key blocks, and API-key or token patterns.
- **One-time release:** approval releases the server-held excerpt once, by ID; the browser cannot substitute different text.
- **Sending:** it goes with the next request only, inside `<build-output>` as untrusted data.
- **Never saved:** the excerpt is not persisted, and excerpt lines a reply quotes are removed from saved history.
- **Separate approvals:** file consent never covers logs, and diagnosis approval never approves an apply or a re-run.

Tested by `CommandServiceTests.outputExcerptIsRedactedPreviewedAndReleasedOnce`, `AssistantServiceTests.diagnosticExcerptIsSentOnceAndNeverPersisted` and the M6 browser journey.
