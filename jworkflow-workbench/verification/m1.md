## WB-05 bounded feasibility probes

### AI adapter — partial protocol evidence, not delivered AI

`ResponsesProbeTests` uses Spring AI 2.0.0 and fake Responses payloads: text/refusal parsing, function definitions, tool-result call IDs, replay of encrypted reasoning, usage, malformed/incomplete/unsupported outputs and retry classification. Configured maximum attempts are measured independently for network, 429, 503, 401 and invalid input. No provider or real tool callback is contacted/executed.

The retained adapter is synchronous and lacks Responses SSE implementation. Provider-request cancellation/stream latency, late-result isolation across actual provider calls, overall deadline and fixed-model enforcement remain unproved. Its experimental runtime options still permit a model override; that is a defect to close before M5, not an approved selector. The experimental bean is disabled by default, including the foundation native build.

Official [model documentation](https://developers.openai.com/api/docs/models/gpt-6-astra) lists `gpt-6-astra` and function calling/streaming; [function-calling documentation](https://developers.openai.com/api/docs/guides/function-calling) is the protocol reference. A bounded authenticated `GET /v1/models/gpt-6-astra` using the existing environment key succeeded and returned the required identifier. No key was printed, no project content was sent and no generation request was made. This verifies model lookup access, not full inference/tools/stream/cancel behavior. Owner: WB-05/WB-18 implementer; live inference/stream/cancel proof remains a technical prerequisite.

### Confinement — negative control rejects insufficient design

`probes/ConfinementProbe.java` creates all benign fixtures under Workbench `target/`, with an `allowed-root` and sibling `outside-root`. It reads/writes only its own fixture, attempts a cache fixture mutation, connects only to its own loopback server, and starts a bounded descendant that writes a marker after the parent exits.

```text
javac -d target/probes probes/ConfinementProbe.java
java -cp target/probes ConfinementProbe
```

Windows results: outside read **allowed**, outside write **allowed**, cache mutation **allowed**, loopback connection **allowed**, descendant survived parent **yes**. Therefore setting subprocess cwd is rejected as confinement. This is a negative-control measurement, not a claim that an OS sandbox was implemented/tested. Product target execution remains disabled.

Windows [AppContainer](https://learn.microsoft.com/en-us/windows/win32/secauthz/appcontainer-isolation) plus job-object confinement still needs concrete prototypes and escape tests. These are investigation candidates, not approved architecture or a weaker trusted-project mode. Real platform enforcement, read-only cache usability, Maven/Gradle success and descendant termination remain blockers owned by WB-05/WB-21. A negative control alone does not satisfy Windows enforced-confinement acceptance.
